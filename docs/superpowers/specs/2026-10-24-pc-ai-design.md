# 电脑端与智能助手实施设计

## 1. 目标与基线

依据 `doc/系统分析与设计说明书.md`（修改后版本）和 `doc/工位级预约细化设计说明.md` 搭建可运行工程。范围是学生/教师 Web、实验室管理员只读 Web、系统管理员 Web、独立实验室签到页、Java 业务服务及新版 FastAPI 智能助手；不创建小程序、微信绑定或扫码页面。

早期定题文档中的 Python 排期微服务不再采用。冲突检测和三套排期算法使用纯 Java；Python 只承担 AI 问答、SSE、短期记忆和预约草稿。

首版验收以真实预约主链路、公共终端、排期与统计、权限和 AI 安全边界为主。生产 HTTPS、备份恢复演练及真实模型平台联调不在无凭据条件下宣称完成。

## 2. 架构与目录

- `server/`：JDK 21、Spring Boot 3.5.16、MyBatis-Plus 3.5.17。唯一业务事实源，包含 REST、RBAC、事务、位图、排期和统计。
- `web/`：Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router、ECharts。只通过 HTTP 调用服务。
- `ai-service/`：Python 3.12、FastAPI、LangChain。只能调用 Java 白名单只读接口，不连接 MySQL，不提供任何写工具。
- `scripts/`：开发环境依赖准备和三个进程的启动/停止，秘密只从用户环境注入子进程。

本机使用 MySQL 8.0.46 `127.0.0.1:3307/lab_reservation` 和 Redis 兼容服务 `127.0.0.1:6379`。测试使用独立的 `lab_reservation_test`，清理前必须断言数据库名，禁止触碰开发库和原 MySQL 5.1。

## 3. 业务设计

### 3.1 身份与权限

角色固定为 `STUDENT`、`TEACHER`、`LAB_ADMIN`、`SYS_ADMIN`。本地账号密码使用 BCrypt；JWT 仅包含用户 ID、角色和过期时间，每次请求复核账号有效状态。Web 令牌存 sessionStorage。

实验室管理员只有查询权限，隐藏按钮不能替代后端 403。`/api/admin/**` 仅系统管理员。学生/教师只能读写自己的预约、信用和申诉。

本地演示账号仅在 `local` profile 创建：`20240001`、`T1001`、`L1001`、`A1001`，统一演示密码 `Lab@2026`。生产不创建这些账号。

### 3.2 48 位资源模型

一天分 48 个 30 分钟片，低 48 位保存占用。开放规则决定可约范围，不改变位索引。输入必须同日、对齐 30 分钟、持续 1–8 片；23:30–24:00 是合法边界，跨午夜申请拆分为多个日期后才能处理。

整室申请要求 `Q & (R OR all S[i]) == 0`；工位申请先检查 `Q & R`，再检查各工位 `Q & S[i]`。工位固定预约写 K 条正式分配并更新 K 个工位位图；整室预约为全部可用工位写正式分配记录，但只更新整室位图。无行等同零掩码。

Redis `resv:lab:{labId}:{date}` 锁包含 UUID token，Lua 按 token 释放。独立事务 Bean 确保事务提交后再解锁。MySQL 事务内先锁用户行防止本人跨实验室重叠，再确保并 `FOR UPDATE` 锁定实验室日行；占用更新同时检查版本和无冲突条件。

FIXED 成功后直接 APPROVED，预约、正式分配、位图和日志原子提交。SCHEDULABLE 保存 PENDING、请求窗口和时长，不占用资源；发布时才写最终实验室和起止时间。教师批次只允许同一实验室的多条不重叠整室明细，任一失败整批回滚。

### 3.3 生命周期与公共终端

状态为 PENDING、APPROVED、IN_USE、COMPLETED、CANCELLED、NO_SHOW、EXPIRED、TERMINATED。所有迁移带原状态条件并追加日志。

开始前不足两小时取消仍成功，同时登记违规并追加信用扣分。签到窗口为开始前后各 15 分钟且包含边界。提前签退只释放当前之后尚未开始的完整时间片；正常结束保留历史占用事实。爽约、违规终止、信用恢复均保留审计流水。

终端先通过终端编码和密钥换取 HttpOnly、SameSite=Strict、限定签到路径的会话 Cookie。学生再输入学号密码，不获得完整 Web 会话。唯一可签到预约直接迁移；多条预约使用 Redis 中 120 秒、一次性选择凭证。连续五次认证失败锁定十分钟，密码和终端秘密不写日志。

### 3.4 排期与统计

三套算法共享同一需求/资源快照，各自创建任务。FCFS 按申请时间；贪心按紧急度、时长适配、信用和碎片惩罚；遗传算法使用锦标赛规模 3、单点交叉 0.8、变异 0.05、精英 5%、贪心解注入，默认 80 个体/200 代。

第二阶段统一落座并计算分配成功率、平均工位利用率、软偏好错配率、时间碎片率及两阶段耗时。只有配置指定的主算法且全部需求已解决时才进入发布；发布重新获取锁、读取占用并原子写入。对照算法仅生成实验数据，永不占生产资源。失败保留 PENDING，不临时切换算法。

统计从预约、分配、签到签退和状态日志计算，区分计划与实际利用率。空数据返回零或空序列，不使用静态假图表。

## 4. AI 服务设计

### 4.1 调用链

Web → `/api/ai/chat/stream`（SSE）或 `/invoke` → FastAPI 身份网关 → Java `/api/internal/auth/verify` → Redis 历史 → LangChain Agent → 三个只读工具 → Java 内部只读接口。

内部接口要求服务凭据；用户 ID 只能来自验证后的上下文，模型不能指定其他用户。工具固定为：

1. `get_reservation_rules(labId?)`
2. `query_lab_availability(labId, date, mode)`
3. `query_my_reservations(status?)`

没有任意 URL、SQL、文件、代码执行、创建/取消预约、签到、规则修改或排期发布工具。

历史键为 `ai:chat:{userId}:{threadId}`，值再次绑定用户；threadId 为 UUID，最多 20 条、TTL 24 小时，追加使用原子 Redis 操作。手机号、密码样式、openid 在历史和模型输入前脱敏，正文不写运行日志。

### 4.2 草稿与降级

`ReservationDraft` 包含 `labId,date,startTime,endTime,allocationMode=FIXED,reservationMode,seatCount,preferences`。Pydantic 负责结构校验；合法结构不代表资源可用。

草稿只回填普通预约表单。用户检查并再次确认后，浏览器使用原 JWT 调用 `POST /api/reservations`，Java 重新做资格、规则和双向冲突校验。AI 永远不直接写业务库。

模型配置延迟到调用时。当前无 API Key，健康检查可显示 `modelConfigured=false`，对话返回 `AI_MODEL_NOT_CONFIGURED` 和普通表单入口。超时、限流、无效输出或 SSE 中断也不得影响普通预约和签到。测试使用假模型与 mock HTTP，不能冒充真实模型联调。

## 5. 桌面视觉与交互设计

受众是中文高校师生和管理员，首要任务是快速判断资源并安全完成预约。视觉方向为“实验室仪器的时间标尺”，不是宣传落地页。

设计令牌：

- `ink #17232B`：侧栏和主要文字。
- `canvas #F3F6F7`：冷灰工作区。
- `surface #FFFFFF`：表单和数据表面。
- `line #DCE5E7`：分隔和时间格线。
- `signal #0E756D`：可操作/可用状态，唯一主强调色。
- `amber #C9822A`、`danger #C84C4C`：待处理与冲突。

正文使用 `Microsoft YaHei UI / PingFang SC`；页面标题和少量关键数字使用 `Georgia / Songti SC`，体现学术记录感；工位号、时间和掩码使用 `Consolas`。背景不使用渐变，装饰只服务于时间与资源含义。

```text
┌──────────┬──────────────────────────────────────┐
│ 品牌     │ 当前位置               用户/终端入口 │
│ 角色导航 ├──────────────────────────────────────┤
│          │ 当前日期与可执行动作                 │
│          │ 关键指标条（紧凑，不做大屏数字）     │
│          │ ┌──── 48 格时间尺 / 工位状态 ──────┐ │
│          │ └──────────────────────────────────┘ │
│          │ 真实图表                 当日预约    │
└──────────┴──────────────────────────────────────┘
```

唯一签名元素是贯穿资源与预约页的 48 格时间尺：开放、占用、选中、冲突都以同一视觉语言表达，既承担品牌识别，也直接完成操作。为此减少普通卡片和无关插画。登录页使用深墨色分栏和同一时间尺，独立签到页则收敛为大字号、低干扰单栏。

交互 120–180ms，遵循 reduced-motion；所有操作有键盘焦点、加载、空态和具体错误。表单失败后保留输入，动作名称保持一致，草稿按钮明确为“回填预约表单”，最终按钮仍为“确认预约”。

## 6. 错误处理与测试

统一 JSON 包装 `code/message/data`，业务错误使用明确 HTTP 状态。参数错误 400、未认证 401、越权 403、资源不存在 404、冲突 409、限流/锁定 423 或 429、模型未配置 503。前端不得把异常吞成成功空态。

- Java：纯算法边界、真实 MySQL/Redis 事务、两种粒度互斥、100 请求争 20 工位、注入失败回滚、批次原子性、签到窗口/一次性凭证、只读权限、主发布与快照过期。
- Python：身份、用户隔离、工具白名单、历史 TTL/裁剪、草稿结构、无 Key 和模型异常降级、SSE 结束事件。
- Vue：路由角色、草稿只回填不自动提交、表单错误保留输入；运行类型检查、Vitest 和生产构建。
- 端到端：真实登录、预约/取消、教师批次、管理员只读、系统管理、终端签到和 AI 降级；浏览器检查控制台与关键页面。

标准验证为 Maven `clean package`、npm `test` 与 `build`、Python `unittest discover`。性能数据只记录实测，不预设通过；真实模型、生产备份和 HTTPS 未验证时明确列出。
