## 1. 系统定位与已落地技术栈

LabSpace 是高校实验室智能预约与排期系统。面向学生、任课教师、实验室管理员和系统管理员，提供整室或工位预约、可调度需求的自动排期、签到签退、信用与申诉、统计，以及 Web 端 AI 预约助手。微信小程序承担学生到场侧的查询、预约、扫码签到与签退（范围以现有页面为准，见第 2 节）。

已落地技术栈如下，不写入仓库中尚未出现的中间件或服务。

| 层次 | 已落地技术 | 证据 |
| --- | --- | --- |
| 业务后端 | Java 21，Spring Boot 3.5.16，Spring Security + OAuth2 Resource Server（JWT HS256），Validation，Spring Data Redis，MyBatis-Plus 3.5.17，Flyway，MySQL 驱动 | `server/pom.xml`，`application.yml`，`SecurityConfig.java` |
| Web | Vue 3，TypeScript，Vite 6，Element Plus，Pinia，Vue Router，ECharts，Axios | `web/package.json` |
| 微信小程序 | 原生小程序，TypeScript，Vitest | `miniprogram/package.json`，`app.json` |
| 智能助手 | Python，FastAPI 0.111.0，Uvicorn 0.30.0，Pydantic 2，LangChain / LangGraph，langchain-deepseek，Redis，httpx | `ai-service/requirements.txt` |
| 数据与协调 | MySQL（Flyway 管理 schema），Redis（预约实验室日期锁、公共签到限流与终端会话、AI 对话历史） | 迁移目录；`RedisLockManager.java`；`PublicCheckinRateLimiter.java`；`ai-service/app/history.py` |

Web 视觉规范以现行 `DESIGN.md`「满幅时间格」为准，不再把对照基线提交主题「松风工作台」当作现行壳层名称。打开 Web、登录后默认进入时间尺；顶栏高 48px、白底，桌面为顶栏横向导航，窄屏把导航收进顶栏下方的菜单，不使用左侧导航边栏或左侧抽屉。窄屏「两列」指时间尺改为上下两列且左栏限制高度，不是导航。四角色共用该壳层，差异在权限与文案。此项属于界面设计约束，不改变下述接口与业务事务边界。

## 2. 逻辑模块结构与职责边界

实现按仓库目录和 Java 包划分，而不是按尚未落地的「独立排期进程」或「权限码服务」划分。

```text
客户端
  web/                 Vue 工作台、运营台、签到终端页、AI 助手页
  miniprogram/         微信小程序（登录绑定、时间尺、预约、扫码签到/签退）
业务后端 server/       唯一业务写入口与事务边界，端口 8080
智能助手 ai-service/   只读问答与草稿，端口 8000，不直连业务库
数据                   MySQL lab_reservation；Redis
```

### 2.3 智能助手边界

FastAPI 校验用户 Bearer，再携 `X-Internal-Service-Token` 调用 Spring `GET /api/internal/auth/verify` 得到服务器确认的 `userId` 与角色。工具仅有 `get_reservation_rules`、`query_lab_availability`、`query_my_reservations`，对应 `/api/internal/rules`、`/availability`、`/users/{userId}/reservations`。对话键为 `ai:chat:{userId}:{threadId}`，默认 TTL 24 小时、最多 20 条。草稿经 Pydantic 校验且 `allocationMode` 只能是 `FIXED`，由前端回填后调用既有 `POST /api/reservations`。未配置 `DEEPSEEK_API_KEY` 时接口降级，不影响普通预约。

## 4. 典型业务时序

### 4.1 固定预约提交（已按代码核实）

接口：`POST /api/reservations`，角色 `STUDENT` 或 `TEACHER`。

1. 客户端提交 `CreateReservationRequest`（分配模式、实验室、日期、起止时间、`ROOM`/`SEAT`、人数或工位数、用途、偏好）。
2. `ReservationService` 经 `ReservationRequestValidator` 规范化，得到 48 位 `TimeSlotMask`（一天 48 格、30 分钟对齐、单次最多 8 格 / 4 小时）。
3. 若 `allocationMode = SCHEDULABLE`：不加实验室日期锁、不改位图；校验信用与候选实验室规则后插入 `PENDING_SCHEDULE` 及初始日志，返回待排期。
4. 若 `allocationMode = FIXED`：`RedisLockManager` 按 `resv:lab:{labId}:{date}` 加锁（等待 3 秒，租期至少 30 秒，Lua 按令牌释放）。
5. `ReservationTransactionService.createFixed` 在事务中：锁定用户并检查 `ACTIVE` 与信用阈值；检查本人有效预约重叠；锁定实验室与整室日位图（无行则先确保零掩码行）；加载工位日位图；`RuleValidator` 校验开放规则；`BitmapConflictDetector` 做双向检测——整室看 `Q & (R | 全部 S[i])`，工位先看整室再由 `GreedySeatAllocator` 选 K 个工位。
6. 检测通过则插入状态为 `APPROVED` 的预约及正式 `t_reservation_seat`；工位模式更新工位掩码，整室模式更新整室掩码（均带版本与无冲突条件，实现细节见 Repository，本文不展开未通读的 SQL）。写初始日志后提交，`finally` 释放 Redis 锁。
7. 冲突或校验失败以业务异常返回，不留下部分占用。

教师批次：`POST /api/reservations/batches`，仅 `TEACHER`。`BatchRequestValidator` 将全部明细规范为 `FIXED` + `ROOM`，最多 14 条、同实验室、批内时段不重叠；按 `labId, date` 排序加锁后在同一事务中逐条走固定预约写入，失败则整批回滚。

现状顺序图见 `doc/uml/oo-design/05_sequence_reservation.current.puml`，不覆盖原 `05_sequence_reservation.puml`。

### 4.2 可调度需求排期（已按代码核实的主路径）

无手动「执行排期」写接口。`ScheduleController` 只有 GET。`ScheduleWorker` 按 `app.schedule.worker.fixed-delay`（默认 60 秒）调用 `ScheduleService.runDueBatches()`：

1. 按日期尝试批次锁，中断未完成任务，加载包含固定占用的共享快照。
2. 为 FCFS、GREEDY、GENETIC 各建任务，按配置标记主算法（种子配置 `schedule.primary.algorithm = GREEDY`）。
3. 依次执行算法并保存候选结果与实验指标（不占资源）。
4. 若主任务 `SUCCEEDED`，则 `PrimaryPlanPublisher.publish(taskId)` 重检并占用；失败由 `SchedulePublicationFailureService` 记录，需求保持待排期。超过期望窗口的待排期由预约定时任务转为 `EXPIRED`。

`PrimaryPlanTransactionService` 的重检 SQL 与失败分类未通读全文，本文不展开到语句级。

### 4.3 智能助手问答与草稿确认（已按代码核实）

开发期：浏览器访问 `/api/ai/**` 由 Vite 转到 `:8000`，其余 `/api/**` 转到 `:8080`。仓库无 Nginx 配置，现状图不应经过 Nginx。

1. Web（学生/教师，`/assistant`）带 Bearer 调用 `POST /api/ai/chat/stream` 或 `/invoke`。
2. FastAPI `authenticated_user` → `AuthGateway` → Spring `GET /api/internal/auth/verify`（同时需要内部令牌）。
3. 读取并脱敏历史，调用带三个只读工具的 Agent；结果经 `ReservationDraft` 校验。
4. 写回 Redis 历史。若有草稿，前端回填表单，用户确认后走第 4.1 节同一预约接口。

小程序目前没有调用 `/api/ai/**` 的页面或 API 封装。已确认：信用、申诉与 AI 当前仅 Web 已有页面，小程序仍为规划。论文若画「小程序 invoke」，须加此注，不把规划写成已实现页面。

## 5. 端到端数据流

典型写路径：

```text
Web 或小程序
  -- Bearer JWT --> Spring Boot :8080
       |-- 事务读写 --> MySQL
       |-- 实验室日期锁 / 签到限流 / 终端会话 --> Redis
       `-- 不经过 FastAPI

Web AI 助手
  -- Bearer --> FastAPI :8000
       |-- 内部令牌 + Bearer --> Spring /api/internal/**（只读）
       |-- 会话历史 --> Redis 键 ai:chat:{userId}:{threadId}
       |-- 可选 --> DeepSeek
       `-- 草稿确认后回到 POST /api/reservations（唯一写预约入口）
```

公共签到终端：`POST /api/checkin/terminal/session` 校验终端编码与密钥，写下 HttpOnly Cookie；随后 `POST /api/checkin/terminal` 与 `/select` 不建立管理会话。生产可打开 Cookie `secure`。

### 6.2 预约与 48 格占用（已按代码核实）

- 一天 48 个 30 分钟格；掩码为 `BIGINT UNSIGNED` 低 48 位，约束 `mask <= 281474976710655`。
- `t_slot_bitmap`：每实验室每日一行整室掩码，兼行锁锚点；无行按 0。
- `t_seat_bitmap`：每工位每日一行；无行按 0。
- `t_reservation.allocation_mode`：`FIXED` / `SCHEDULABLE`；`reservation_mode`：`ROOM` / `SEAT`。
- 状态：`PENDING_SCHEDULE`，`APPROVED`，`IN_USE`，`COMPLETED`，`CANCELLED`，`NO_SHOW`，`EXPIRED`，`VIOLATION_TERMINATED`。
- V4 增加 `seat_count`；V7 签退渠道含 `WEB_ACCOUNT`；V5 允许结束时刻为次日 00:00。

定时任务（`ReservationScheduledJobs`，在 `app.reservation.jobs.enabled=true` 时随 `@EnableScheduling` 生效）：已通过且超过签到宽限未签到 → `NO_SHOW`；使用中且已到结束时间 → `COMPLETED`；待排期超过窗口结束 → `EXPIRED`。

`VIOLATION_TERMINATED`（违规终止）在状态枚举中存在。已读全部 `*Controller.java`，未见管理员将预约写成该状态的写接口。这是已知缺口，不编造接口。未逐方法证明服务层内部不存在该迁移。

配置表另有 `schedule.batch.interval.minutes = 10`。该键存在于种子数据。Worker 使用的默认周期是 `app.schedule.worker.fixed-delay` 60 秒。该配置键是否被读取待后续核对，本文不把它写成已核实的调度周期。

### 6.3 角色

V2 种子：`STUDENT`，`TEACHER`，`LAB_ADMIN`，`SYS_ADMIN`。路径规则：`/api/admin/**` 仅系统管理员；其余默认需认证，细粒度由 `@PreAuthorize` 与查询侧的「是否管理员」判断共同约束。JWT 有效期默认 2 小时，鉴权时回库取角色并拒绝非 `ACTIVE` 用户。

## 8. 可供「系统设计」章使用的结论性表述（勿当作已测性能指标）

1. 系统采用前后端分离的四端结构：Vue Web 与微信小程序作为客户端，Spring Boot 作为唯一业务事务与资源占用写入口，FastAPI 作为可选的只读智能助手，MySQL 持久化业务数据，Redis 承担锁、短时凭证与对话历史。
2. 一天固定划分为 48 个 30 分钟时间片，以 48 位整型掩码分别记录整室占用与工位占用；整室申请与工位申请在同一实验室日期上双向互斥。
3. 固定时空预约在提交事务成功后进入已通过，并同时写入正式座位分配与位图；可调度需求提交时不占位，由进程内定时 Worker 在共享快照上运行三种算法，仅主算法合格方案经重检后发布。
4. 访问控制按四角色实施：路径级与方法级角色校验相结合，JWT 请求时回库确认用户状态与角色。权限码表已存在，但不是当前请求鉴权的依据。
5. 实验室管理员不能调用 `/api/admin/**` 写接口，但可以只读查询排程、统计和预约使用情况；资源、用户、规则与申诉核定由系统管理员执行。
6. 开发期的请求分流由 Vite 完成：`/api/ai/**` 到 8000 端口，其余 `/api/**` 到 8080 端口。图 4-7 中的 Nginx 或独立 8081 排期进程属于目标部署，仓库尚未落地。
7. 分配结果、爽约与申诉核定结果由用户自行查询。已枚举的服务端包中未见消息推送、订阅通知或邮件服务类；该结论基于目录枚举与 Controller 阅读，不是全库字符串穷尽搜索。
8. `GET /api/ai/health` 按现状是无登录健康检查。
